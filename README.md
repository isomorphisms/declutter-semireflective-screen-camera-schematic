Recover readable views of the photographed ReTech control and power schematics,
while retaining the distinction between observed circuit marks, image
enhancement, and unresolved joins.

The inputs are photographs of **scrolled HMI viewports**. The screen frame,
reflected photographer, and dust are often stationary while the diagram moves.
Those stationary objects are therefore unsuitable panorama-registration features.

## Current implementation

The program reads binary RGB P6 PNM, validates its dimensions and exact payload
length, applies explicit integer local-contrast settings, and writes P6 PNM.
It also copies bounded rectangles into a section layout without rescaling.
All image processing is in the `.idric` sources under
[`examples/autogenerated/schematic-cleanup`](examples/autogenerated/schematic-cleanup).

JPEG decoding and PNG encoding are external format boundaries. They do not
perform the cleanup. The decoded source pixels and the enhanced pixels remain
separate images.

| Source | Responsibility |
| --- | --- |
| `SchematicRaster.idric` | P6 admission and output, dimension-indexed raster and coordinate types, integer local-background calculation, bounded crops and copies |
| `Cleanup.idric` | Enhancement and crop commands, with transformation records |
| `Assemble.idric` | Checked section layout, destination-overlap rejection, visible gutters at unresolved joins |
| `layouts/control.tsv` | All six distinct control sections, with a clearer alternate observation for the bottom-left section |
| `layouts/power.tsv` | Four power sections in their correct arrangement |

Each layout line records a source rectangle and a destination origin. For a pixel
inside that rectangle, its source coordinate is exactly the output coordinate
minus the destination origin plus the source origin. One source pixel becomes
one output pixel. Grey gutter pixels are layout background and have no source
in the schematic.

The local-contrast operation subtracts a per-channel neighbourhood mean, removes
the explicitly chosen noise offset, applies an integer gain, and clips at the
RGB limits. Its exact equation is in `normalize_sample`. It preserves neither
the original brightness nor every faint mark. It is a **lossy readability view**,
not proof that reflection and circuit content have been separated correctly.

## Input coverage and unresolved registration

[`source-manifest.tsv`](source-manifest.tsv) identifies all twelve original
photographs by digest and dimensions. They are each 1152 × 1536 pixels. Raw
photographs containing the photographer's reflection are not included here.

The six control sections are 1712, 1713, 1714, 1715, 1716, and 1717. Photos 1718
and 1719 repeat the bottom-left section. The selected layout uses 1718 because
it includes left-margin captions cut off in 1714. Power is arranged with 1720
over 1723 on the left and 1721 over 1722 on the right.

Several overlaps contain only one usable circuit row or heavily obscured marks.
There is no verified geometric overlap between the left and right halves.
The current output therefore preserves separate sections with gutters. It does
**not** claim a seamless geometrically registered schematic or draw conductors
across missing observations.

[`registration/landmarks.tsv`](registration/landmarks.tsv) retains candidate
shared circuit features and their visual estimation uncertainty. A fit through
exactly three guessed points would not independently establish correctness.

## Historical initial raster execution and evidence

The compiler dependency is the canonical `isomorphisms/Idric` `Idriç` line,
pinned to `2bce7677f513d711875e978bd6f5ad28b9e54d58`. Its maintained `edric`
entrypoint and Chez host execution path are used. No RefC, generated-C image
processor, Python image implementation, or generative redraw is part of this
program.

The command interfaces are:

| Executable | Arguments |
| --- | --- |
| `cleanup` | `enhance INPUT.ppm OUTPUT.ppm RADIUS GAIN NOISE` |
| `cleanup` | `crop INPUT.ppm OUTPUT.ppm LEFT TOP WIDTH HEIGHT` |
| `assemble` | `LAYOUT.tsv INPUT_DIRECTORY OUTPUT.pnm` |

Compilation, synthetic runtime acceptance, and processing of all twelve
photographs passed through that pinned compiler. The chosen photograph settings
are radius 24, gain 8, noise subtraction 3. The control layout is 2328 × 3720;
the power layout is 2328 × 2230. Both retain native source sampling. Broad
reflections are weaker, but their edges, dust, navigation buttons and some
frame content remain. Glare-obscured information has not been recovered.

Compiler, execution, verification, and remaining limitations are recorded in
[`examples/autogenerated/schematic-cleanup/attempt.md`](examples/autogenerated/schematic-cleanup/attempt.md)
and [`evidence/host/acceptance.tsv`](evidence/host/acceptance.tsv).
The real-photograph result has its separate
[`evidence/photo-run.tsv`](evidence/photo-run.tsv) record.
Passing raster checks do not establish successful optical reconstruction.

## Historical registration trial and executed continuation

The [registration continuation](docs/registration-v2.md) provides fixed-point
Idriç source selection across three landmark-supported overlapping pairs,
explicit seam choices, measured leave-one-out errors, and pixel-mapped
reference trials. This is **not seamless stitching of the entire diagram**:
the 1712–1713, 1713–1718 and 1715–1716 control joins remain unregistered.
The 1721–1722 power pair lacks independent feature corroboration.

`Registration.idric` and `RegistrationTests.idric` now compile and execute through
the pinned compiler. [The executed continuation](docs/acceptance-v3.md) records
the current plans, tests, full photograph processing and private sheet dimensions.
The earlier image trials remain separate historical evidence. Electrical
continuity and full photographic reconstruction remain unaccepted.
